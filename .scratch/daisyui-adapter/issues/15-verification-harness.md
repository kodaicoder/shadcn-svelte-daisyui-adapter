# Verification harness

Type: task
Status: resolved
Blocked by: none

## Question

Nothing on this map can be proven without a disposable project to install into. Build the harness before the prototype needs it.

Required:
1. A script (node or shell) that creates a fresh SvelteKit project in a temp directory, runs `shadcn-svelte init` non-interactively, and leaves it ready for `add`.
2. A way to point that project's `add` at a locally served registry JSON, so the harness does not depend on the public deployment.
3. A build step that fails loudly when the CSS or the plugin throws.
4. Screenshot or DOM evidence of at least one rendered component in light and dark.
5. Cleanup, and a `--keep` flag for debugging.

Constraints: never touch the current repo's own dev server, use a dedicated port, and keep the temp directory outside the repo. Follow the repo's existing `verify` skill conventions where they fit.

## Answer

Done 2026-10-28. Harness at `.scratch/daisyui-adapter/harness/`:

- `run.mjs` scaffolds a SvelteKit 3 project, installs dependencies, reproduces shadcn step 4, adds a baseline component, optionally installs a registry item, builds, renders light and dark, and writes evidence.
- `shot.mjs` drives the rendered page with Playwright and captures screenshots plus computed styles and console errors.

Run:

```
node .scratch/daisyui-adapter/harness/run.mjs [--keep] [--add <url>] [--registry <dir>] [--port <n>]
```

Proven on a clean run: `exit=0`, `build: true`, HTTP 200, 3 buttons rendered, no console errors, port 5209 freed afterwards. Evidence lands in `harness/runs/<timestamp>/` (`light.png`, `dark.png`, `result.json`, `build.log`, `run.json`).

Two findings that shaped it:

1. **`shadcn-svelte@1.7.1 init` cannot run unattended.** It requires a preset id generated by shadcn-svelte.com/create; `--preset mira` and `--preset default` are both rejected, and without a preset it opens an interactive picker. The harness therefore reproduces step 4 directly: it copies this repo's `src/routes/layout.css` as the global CSS, adds the import to `+layout.svelte`, copies `src/lib/utils.ts`, and writes `components.json` with `tailwind.css` pointed at `src/app.css`. This is the same end state a user reaches through the wizard.
2. **SvelteKit 3 moved configuration.** There is no `svelte.config.js`; the adapter lives in `vite.config.ts` under `sveltekit({ adapter })`, and the default alias is `#lib`, not `$lib`.

Constraints: the harness reads this repo's `layout.css` and `utils.ts`, so it tracks whatever theme this repo currently carries. It installs `@sveltejs/adapter-node` because `adapter-auto` cannot build outside a known platform. It uses ports 5209 (app) and 5199 (registry) and kills the server process tree on Windows.

Written to `.scratch/daisyui-adapter/research/` is not applicable; the evidence lives under `harness/runs/`.
