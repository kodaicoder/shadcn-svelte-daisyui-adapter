# Override and re-run policy

Type: grilling
Status: open
Blocked by: 13

## Question

A team will regenerate their daisyUI theme and re-install, and they will want one or two tokens to differ from the derivation.

Decide:
1. The escape hatch syntax: a separate `daisyui-adapter.overrides.css` the user owns, a marker-fenced block inside the generated CSS, or plugin options.
2. Precedence: user override beats generated binding, always. State where it sits in the file so source order guarantees it.
3. Re-run behaviour: re-running `add` overwrites the generated file. What happens to user overrides, and what happens to hand edits inside the generated region.
4. Drift detection: should the build warn when the theme file changed but the generated output did not, or is generation always live at build time so drift cannot exist? Answer this given the plugin architecture.
5. Whether the theme file needs a `generated by` marker or version header.

Depends on ticket 13 for where the bindings live.
