Closed 2026-11-11 on `fix/nutchapon/ai/contrast-warning`, which is this ticket's base and its own
branch; nothing merges back to `develop` or `main`.

- One plain `@theme` block carries the six rungs and their line heights, 10/14 through 20/28. It is a
  plain block, not `@theme inline`, because an inline block does not emit its variables and
  `calc(var(--text-base) * 2)` would resolve against nothing. `init` and `map` rebuild the block from
  `targets/type-scale.mjs`; a second run is byte-identical.
- Every component class string moved one rung up, so the rendered px is unchanged. A hand-written row
  per rung was incomplete: a string another site edits without touching its rung (the label's cursor
  insert) hides the unshifted token. The shift is now `targets/text-rungs.mjs`, 119 rows over 109 stock
  files, generated by `tools/generate-text-rungs.mjs` and applied last.
- The field sizes read their token: `sm` `--text-sm`, `default` `--text-base`, `lg` `--text-lg`.
  Height is 2×, textarea `min-h` 4× and padding-x 0.5×. Measured before and after the shift on input,
  textarea and native select: 12/24/6, 14/28/7, 16/32/8.
- Radius stays on its steps, the border stays 1 px, and the page and component spacing are untouched.
- The field journeys read `--text-*` from `:root` and compute the box and padding from it, so a table
